title: Health and observability
subtitle: Make dependencies visible in production
---

Use `createHealthRegistry` to register checks for databases, caches, queues, and external services.

```ts
import { createHealthRegistry } from '@hedronjs/jeston';

const health = createHealthRegistry();
health.register('database', async ({ signal } = {}) => {
  await db.query('select 1', { signal });
  return { status: 'ok', tags: ['critical'] };
});

const report = await health.report({ timeoutMs: 2_000 });
```

A report contains an overall `ok`, `degraded`, or `down` status, each check result, measured latency, optional tags, and an ISO timestamp. Checks receive an abort signal when the report deadline expires. A check that cannot finish before the deadline is recorded as `down` without blocking the complete report.

## HTTP endpoints

Supply the registry in `AppConfig.health` to enable `/health` and `/ready`. Customize them with `healthPath` and `readinessPath`. The endpoints return JSON with `Cache-Control: no-store`; non-`ok` reports return `503`. Use readiness to control traffic admission and keep liveness policy specific to the hosting platform.

## Metrics and logs

Request IDs are enabled by default. Completion logging can be disabled in production to reduce hot-path I/O. `MetricsAdapter` can receive request counters, duration histograms, cache counters, gauges, and bounded flush/close operations. Add an adapter for metrics and tracing; measure request rate, error rate, latency percentiles, database pool saturation, queue depth, cache hit ratio, memory, and event-loop delay.
