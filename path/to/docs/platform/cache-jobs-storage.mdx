---
title: Cache, jobs, and storage
subtitle: Use stable contracts for distributed platform services
---

Jeston defines interfaces for cache, job queues, object storage, and metrics. These interfaces allow a local implementation during development and a distributed provider in production.

## Local response cache

`ResponseCache` is process-local and disposable. It supports `get`, `getFresh`, TTL, a stale-while-revalidate window, concurrent-miss deduplication, tags, tag invalidation, a configurable `maxEntries` limit, LRU-style eviction, and basic counters through `getStats()` or `onMetric`.

```ts
const cache = new ResponseCache({ maxEntries: 10_000 });
const value = await cache.remember('profile:1', loadProfile, {
  ttl: 30,
  staleWhileRevalidate: 60,
  tags: ['profile:1']
});
```

A stale value can be returned while one revalidation runs. A distributed adapter may have different consistency and eviction semantics; document those semantics and never make cache the only source of truth.

## Jobs

A `JobQueue` accepts a name, payload, delay, and optional idempotency key. Add tags and a maximum attempt count when the adapter supports them. Workers must still make side effects idempotent, retry transient failures, and route permanent failures to a dead-letter workflow.

```ts
await queue.enqueue('train-evaluation', { runId }, {
  idempotencyKey: `evaluation:${runId}`,
  maxAttempts: 5,
  tags: ['evaluation']
});
```

## Storage

A `StorageAdapter` supports streaming uploads, reads, and deletes. Pass an abort signal for request-scoped uploads/downloads. Use object storage for production files rather than local disk when the application can scale horizontally.

## Provider selection

| Requirement | Development | Production |
| --- | --- | --- |
| Cache | Memory adapter | Redis or managed cache |
| Jobs | Local fake | Durable queue with retries |
| Files | Temporary local storage | S3-compatible storage |
| Metrics | Console adapter | OpenTelemetry/Prometheus adapter |

The core does not ship provider SDKs. Choose an adapter that documents its Node version, failure behavior, retries, security policy, shutdown behavior, and operational limits.
